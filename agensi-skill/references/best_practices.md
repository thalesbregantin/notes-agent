# 🧠 Obsidian Second Brain & Note-Taking Best Practices

Guidelines for structuring notes, managing metadata, and preserving vault hygiene with `notes-agent`.

---

## 1. Frontmatter Convention

Every note generated by `notes-agent` follows standard YAML frontmatter so it is fully compatible with Obsidian plugins like **Dataview**, **Omnisearch**, and the **Graph View**:

```yaml
---
title: "Título da Nota"
date: 2026-11-13
origin: "reuniao" # ou artigo, ideia, livro, podcast
status: "ok"     # ou needs_review se houver afirmações não confirmadas
tags:
  - tech
  - arquitetura
  - langgraph
---
```

---

## 2. Note Structure & Linking

- **Atomic Notes**: Each note should capture one core concept, decision, or meeting.
- **Wikilinks**: Connect related concepts using double brackets (e.g., `[[Arquitetura RAG]]`, `[[Reuniões Q4]]`).
- **Action Items**: Use checklist format for clear visibility in Obsidian:
  - [ ] Action item com responsável e prazo.

---

## 3. Reviewing `needs_review` Notes

When `notes-agent` detects that a generated note contains statements that were not strictly supported by the provided source text:
1. The note frontmatter receives `status: "needs_review"`.
2. A callout banner is placed at the top of the file highlighting the specific unverified assertions.
3. The user can simply edit the highlighted bullet points or delete the callout once verified.
